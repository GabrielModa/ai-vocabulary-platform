# ADR-064 — Study-session snapshot persistence

## Status

Accepted.

## Context

Task 063 defined an immutable and versioned study-session snapshot. The database package previously
contained only platform infrastructure tables.

A saved session must preserve the exact published exercises selected when study begins. Rebuilding
that content later from candidates, providers, or AI would make historical sessions unstable.

## Decision

Add a `study_session_snapshots` table and a database repository.

The table stores the deterministic session ID, snapshot version, title, level, canonical creation
timestamp, ordered exercise IDs, and the complete snapshot as JSONB.

Saving is idempotent:

- a new ID and snapshot returns `created: true`;
- the same ID and same snapshot returns `created: false`;
- the same ID with different content returns a typed conflict and never overwrites data.

Loading returns a newly frozen snapshot. The repository does not generate IDs, call a clock, rebuild
exercises, or import web response types.

The migration is generated by the repository's existing `drizzle-kit` workflow so its SQL, snapshot,
and journal remain synchronized.

## Consequences

Study sessions can be resumed from the exact published content selected by the learner. The next
checkpoint can expose authenticated application operations for creating and retrieving sessions.

## Rollback

Remove the repository, table definition, generated migration artifacts, tests, exports, ADR, and
Task 064 document.
